### Implement Admin Alert Bar Messaging System

Task Overview Develop a simple messaging system for admin users. Implement an alert bar display on the application. Key Goals Admin message creation : Allow admins to write custom alert messages. Alert activation/deactivation : Enable admins to set alerts as active (red display) or cleared (green notification). User interaction : Users should be able to clear the green notification alert via a close button. Why This Matters Enhances critical communication from administrators to application users. Provides clear visual cues for active alerts and cleared notifications.

### Acceptance Criteria

• [ ] **Admin Message Creation:** Admins can create alert messages with a maximum character limit of 255 characters. The message should be stored in the database.

• [ ] **Alert Activation/Deactivation:** Admins can set the alert status to "Active" (displays as red bar) or "Cleared" (displays as green bar) through a toggle/switch in the admin panel. The status is persisted in the database.

• [ ] **Alert Bar Display:** The alert bar is displayed at the top of the application for all users after login. It should display the active/cleared message from the database.

• [ ] **User Dismissal of Cleared Alerts:** Users can dismiss the green "Cleared" alert bar by clicking the close button ("X"). Dismissal is persistent for the user's session (using local storage). If the alert is changed to "Active" by the admin, the alert bar will reappear for all users on their next login or page refresh.

• [ ] **Edge Case: Empty Message:** If the admin sets the alert message to an empty string, the alert bar should not be displayed.

• [ ] **Edge Case: Database Error:** The application gracefully handles database connection errors when retrieving alert messages, displaying a generic error message in the admin panel (e.g., "Error retrieving alert message"). The user-facing app should not display any alert bar if there's a database retrieval error.

• [ ] **Security:** Ensure that HTML tags are properly escaped in the alert message to prevent XSS (Cross-Site Scripting) vulnerabilities.

### Testing Requirements

• [ ] **Functional Tests:** Verify that admins can create, activate, and deactivate alerts and that the alert bar displays correctly based on the alert status.

• [ ] **UI Tests:** Verify the alert bar's visual appearance (color, text) and the functionality of the close button. Test on different screen sizes (responsive design).

• [ ] **Database Tests:** Verify that alert messages and their status are stored and retrieved correctly from the database.

• [ ] **Security Tests:** Perform XSS injection attempts to ensure the application is protected against malicious scripts in the alert message.

• [ ] **User Acceptance Testing (UAT):** Have a group of users (admins and regular users) test the functionality and provide feedback.
